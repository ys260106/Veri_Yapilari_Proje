Ortak isimler: herkes bunlara göre yazar

  • Paket ve klasörHer dosyanın ilk satırı package kutuphane;, hepsi src/kutuphane/ altında. Kök dizinde .java kalmaz.
  • Tek modelKitap, KitapKopyasi, Uye, Odunc, BeklemeTalebi projede birer kez var. Kimse kendi dosyasının içine ikinci bir Kitap yazmaz.
  • Numaralar intuyeNo, kitapNo, kopyaNo, oduncId, talepId hep int. kopyaNo bütün sistemde tektir; o yüzden metotlar kitapNo + kopyaNo değil, sadece kopyaNo alır.
  • Getter adlarıgetAd(), getYazar(), getYayinYili(), getKitapNo(), getKopyaNo(), getUyeNo(), getBeklenenIade(). getBaslik() yok.
  • Kopya durumuKitapKopyasi.RAFTA, ODUNCTE, AYRILDI sabitleri. Durumu sadece OduncServisi değiştirir.
  • Liste düğümü deseniUye'deki gibi: model sınıfında public sonraki/onceki, listede bas, son, boyut, getBas(), diziyeCevir().
  • Hazır koleksiyon yokjava.util içinden List, ArrayList, HashMap, LinkedList, Queue yok. Tarih için java.time.LocalDate kullanılıyor (veri yapısı değil).
  • Hata bildirmeKurala aykırı işlemde metot IllegalArgumentException("açıklayıcı Türkçe mesaj") fırlatır; panel yakalayıp JOptionPane ile gösterir. Servislerde System.out ile hata basılmaz.
  • ArayüzSwing. Her panel XPanel extends JPanel, kurucusu XPanel(Kutuphane k). Sekmeleri sadece AnaPencere ekler.
  • mainUygulamanın tek main'i Main.java'da. Herkesin kendi testi UyeKitapTest, OduncTest, SorguTest, SiralamaTest.
  • Dosya biçimiHer satır bir kayıt, alanlar ; ile ayrılır. Örnek uyeler.txt: 101;Ali Yılmaz
  • READMEHerkes sadece kendi bölümünü düzenler; böylece birleştirmede çakışma olmaz.

Birleştirme: bağımlılık sırasıyla, her adımda derleyerek

Kimse doğrudan main'e push etmez. Her parça kendi dalından Pull Request ile gelir; sıra, bir dosyanın kullandığı sınıfın main'de önceden var olmasına göre belirlendi.

  1. Toplantı ve temizlik (bugün)

    Bu sayfadaki isimlerde anlaşın. Yusuf, main'deki kök dizindeki sorgulama.java'yı siler (derlenmiyor, içinde ikinci bir Kitap var). Herkes kendi dalındaki dosyaları src/kutuphane/'ye taşır ve paket satırını ekler.

  2. Pull Request sırası

    1. kayit-ve-silme: Uye, UyeListesi, Kitap, KitapKopyasi, KitapListesi. Kimseye bağımlı değil, herkes buna bağımlı.
    2. sorgulama-modulu, 1. parça: KendiHashMap, HashDugumu, DinamikDizi. Faruk'un OduncServisi bunları kullanır.
    3. odunc-sistemi: Odunc, BeklemeTalebi, Kuyruk, OduncListesi, OduncServisi, OduncTest.
    4. sorgulama-modulu, 2. parça: SorguSistemi, SorguTest (OduncListesi'ne ihtiyaç duyar).
    5. siralama-modulu: KutuphaneSiralama, DosyaIslemleri, Kutuphane, Main, AnaPencere (henüz sekmesiz), SiralamaTest.
    6. Paneller: herkes kendi panelini kendi dalından gönderir; birleşince Ömer AnaPencere'ye o sekmenin satırını ekler.

    İlk PR'lar iskelet olabilir (alanlar + metot imzaları, gövde boş veya return null;). Önemli olan imzaların erken main'de olması; içerikler sonraki PR'larla dolar.

  3. Her PR'dan önce: main'i kendi dalına al ve derle

    GitHub Desktop

    Current Branch → kendi dalın · Branch → Update from main · derle · Push origin · Create Pull Request (hedef: main).

    Komut satırı

    git checkout odunc-sistemi      # kendi dalın
git pull origin main             # main'deki son hali al
javac -d out src/kutuphane/*.java
git push origin odunc-sistemi

    Derleme hatasızsa PR aç. Bir PR main'e girince diğer üç kişi aynı "Update from main" adımını tekrarlar.

  4. Başkasının dosyasına dokunma

    Bir sınıfa metot lazımsa (örneğin Faruk'a KitapListesi.kopyaBul) sahibine yazılır, sahibi ekler. Böylece hem çakışma çıkmaz hem de herkesin GitHub katkısı kendi adına görünür.

  5. Son kontrol senaryosu (main'de)

    Üye 101 ve 102 ekle → kitap 1 ve kopya 500 ekle → 101'e ödünç ver → 102 sıraya girsin → 101 iade etsin → kopya AYRILDI olmalı → 103 alamamalı → 102 alabilmeli → kapat, aç: veriler txt'den geri gelmeli → sıralama ve gecikenler sekmesi doğru çalışmalı.
